# Theory 08A — Final Prompt Compiler and Aesthetic Recovery

## Purpose

Structural validation protects the drawing from scale, anatomy, contact, and
object failures, but the final image model should not receive the validator's
field names or legalistic checklist prose. The last pre-image step must compile
the approved structure back into compact visual language.

## Decision rule

Before `PRE_IMAGE_HANDOFF_READY: yes`, run this sequence:

1. **Structure lock summary** — summarize only the highest-risk structure that
   must survive: scale witnesses, contact target, protected chains, grip/cut
   mechanics, object separation, user camera-class lock, and user
   non-negotiables.
2. **Aesthetic recovery** — restore the image's commercial illustration read:
   face/eye focal priority, composition pressure, background pressure frame,
   value masses, line/shape hierarchy, palette/accent discipline, and texture
   density zoning.
3. **Limited negatives** — keep only concrete failure defenses tied to prior
   failures or high-risk structure. Do not dump every validator rule into the
   negative prompt.
4. **Final compiled prompt** — write the handoff as natural image language. Do
   not include schema names such as `SCALE_VISUAL_GUIDE_PACKAGE`, tier labels,
   verdict keys, object IDs, gate names, or validator instructions.

## Aesthetic recovery checklist

- Does the face/eye read remain the first focal target?
- Does the composition still have pressure, framing, and flow rather than a
  neutral centered character sheet?
- Does the background act as a pressure frame/world mass, not empty wallpaper?
- Are value groups and edge hierarchy readable at reduced size?
- Are line, shape, color accent, and texture density organized into clear
  layers instead of uniform polished anime rendering?
- Did structural locks make the prompt stiff, CAD-like, or over-explained? If
  yes, keep the structure but rewrite the surface as painterly image language.

## Prompt compiler rules

- Keep registry IDs, field names, and gate names inside the spec.
- Convert visual-guide facts into concrete visible outcomes:
  - "long tram cabin with repeated window/door bays and tiny passenger
    silhouettes"
  - "visible neck cross-section, not hidden by cloak or effects"
  - "katana hilt seated in her palm with thumb opposition and neutral wrist"
- Put hard structure first only when it is scale/action critical; otherwise let
  the final prompt open with the strongest imageable composition/focal sentence.
- If scale is camera-critical, the prompt must open with the user-approved or
  repaired camera class in natural image language: "extreme wide scale shot",
  "wide establishing scale shot", "no close-up", "full container visible",
  "small protagonist", and visible door/window/passenger/module witnesses.
- Face/eye priority can survive scale-critical wide shots only as small bright
  accents. Do not let portrait, face-first, or medium hero language lead the
  prompt until the scale verdict has passed.
- Keep style guidance operational: line weight, value grouping, palette, accent,
  texture, background pressure, and face/eye treatment.
- If source image pixels/control references cannot be passed into generation,
  label the run as descriptive reinterpretation / prompt-only fallback. Do not
  claim true image development or source-conditioned editing.

## Failure state

The compiler fails if the final prompt reads like a validator report, contains
schema jargon, repeats a flat registry, loses face/eye focal priority, loses
background/composition pressure, lets negative rules dominate the image
language, or buries a scale-critical camera/shot-class repair after character
beauty/style/action wording.
