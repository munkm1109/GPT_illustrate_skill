📐
3D Perspective Pre-Verification
모든 오브젝트를 투시법 위에서 3D로 먼저 계산·고정

일반 AI 이미지 생성은 카메라 각도, 소실점, 오브젝트 배치를 전부 모델의 "학습된 감"에 위임한다. 결과적으로 손·발·배경 구조물이 공간적으로 붕괴되거나 뭉개지는 현상이 반복된다.

illustrate-skill은 Step 2.1~2.8에서 Blender로 장면 전체를 3D primitive로 blockout하고, 카메라 위치·horizon line·vanishing point·접지면·오브젝트 스케일을 수학적으로 고정한 뒤, clay / lineart / depth 패스와 투시선·스케일 마커를 visual guide composite로 합쳐 사용자 확인을 받는다. 승인된 composite와 lineart/depth 패스를 image_gen handoff package로 묶어 ControlNet-like 구조 참조로 이미지 생성기에 넘긴다. 이미지 생성기는 스타일 번역만 담당하고, 공간 구조 계산은 하지 않는다.

결과: AI 특유의 구조 뭉개짐이 극소화된다.

System Advantages
다른 구조적 강점

3D 투시 외에도 이 시스템이 제공하는 장점들.

01
Theory-Gated Execution
매 단계마다 이론 파일(theory-*.md)을 먼저 읽어야만 실행이 허용된다. "감으로 그리는" 게 아니라 THEORY → DECISION RULE → EXECUTION → OUTPUT → CHECK 순서를 강제 통과시킨다. 이론을 읽었다는 theory-read-proof artifact가 없으면 다음 단계로 넘어갈 수 없다. references/theory-*.md
02
Spec-First — No Raw Prompt
사용자 요청이 이미지 생성기로 직행하는 경로가 없다. Step 1~8 + 2.1~2.9, 총 16개 이상의 구조 결정을 채운 설계서(spec artifact)를 먼저 완성해야 한다. 설계서 없이 이미지 생성은 시스템 레벨에서 차단된다. illustrate-spec-template.md
03
Automated Script Validation Gates
이미지 생성 직전에 두 개의 Python 스크립트가 자동 게이트로 작동한다. validate_illustrate_spec.py는 필드 누락·placeholder·theory proof 미생성을 차단하고, run_illustrate_pipeline.py는 PIPELINE READY 여부를 최종 확인한다. 사람의 판단이 아닌 코드가 게이트를 지킨다. scripts/
04
Perspective-Plane Object Inventory
장면 안의 모든 오브젝트를 투시 평면별로 목록화한다. "도시 배경", "기계 느낌" 같은 뭉뚱그리기는 금지다. support plane / vertical plane / overhead / background depth 중 어느 평면에 있고 어떤 역할을 하는지 명시해야 다음 단계가 열린다. Step 2.2 Object Inventory
05
Anatomy-as-Object-Stack
인체를 감으로 그리지 않는다. age/sex/body-type → 흉곽·골반 비율 → 팔다리 비례 → 손 → 손가락 → 소품 접촉으로 이어지는 오브젝트 스택으로 잠근다. 손만 따로 예쁘게 맞추는 것은 시스템 레벨에서 금지된다. Step 2.3 Anatomy Gate
06
Full Artifact Traceability
모든 결정이 파일로 추적된다. spec ← theory proof ← object research artifact ← invocation log ← Blender .blend ← render passes ← visual guide composite ← user feedback ← pipeline prompt. 어느 단계에서 무엇을 결정했는지 나중에 완전히 재현할 수 있다. .omx/runs/
07
Thin Style Wrapper Architecture
스타일 스킬은 base illustrate-skill을 복사·파괴하지 않는다. reference-copy-skill로 만든 style-pack을 얇은 wrapper로 얹는 구조다. Huke, Redjuice 등 어떤 스타일도 base process 위에 독립적으로 쌓인다. 스타일을 추가해도 검증 로직은 그대로 유지된다. derived-style-skills/
08
Structure-Preserving Source Upgrade
기존 이미지를 업그레이드할 때 원본 오브젝트의 정체성을 보존한다. 약한 구조를 glow·blur·noise로 덮는 것이 금지된다. 원본 오브젝트를 Step 2.2에 명시하고, 그 구조 위에서만 스타일을 번역한다. Step 10 Source Upgrade Rules
09
Object Relationship Verification
개별 오브젝트 조사 후, 오브젝트들이 서로 맞게 배치되는지 별도로 검증한다. 스케일 관계·occlusion 순서·접촉과 지지·충돌 체크·재질-조명 상호작용이 Step 2.6~2.7에서 확인된다. 손이 소품을 "장식처럼" 붙이는 것은 이 단계에서 차단된다. Step 2.6, 2.7
10
Step-by-Step Critique Mode
기존 그림·프롬프트를 Step 1~8 기준으로 단계별 진단하는 CRITIQUE 모드가 내장된다. 결과가 나쁠 때 "느낌이 별로"가 아니라 어느 단계의 어떤 결정이 원인인지 추적할 수 있다. 사용자 판정이 1차 verdict이고, 시스템이 그 이유를 진단한다. CRITIQUE mode

Operation Modes
세 가지 실행 모드
SPEC
새 장면·이미지를 설계할 때. "그려줘", "구도 잡아줘" 같은 요청의 기본 모드. Step 1~8 전체를 실행한다.
→ spec artifact · theory proof · handoff prompt
CRITIQUE
기존 그림·프롬프트를 Step 1~8 기준으로 단계별 진단. 사용자 판정이 1차 verdict이고 시스템이 원인을 분석한다.
→ User Verdict · System Read · Next Move
EXTEND
새 이론 파일 추가, 프로세스 단계 수정. 이 시스템 자체를 발전시킬 때 사용한다.
→ 새 theory-*.md · main-process.md 업데이트
Execution Pipeline
SPEC 실행 체인 (render-bound)

이미지 생성이 목표인 요청의 전체 단계.

Step 1 — Intent
시간·환경·역할·행동·감정축을 1문장으로 고정. 추상어("멋진", "분위기 있는") 금지.
Step 2 — Silhouette & Composition
구도 타입·검은 덩어리 위치·시선 흐름·무게중심 고정. 얼굴 디테일 이전에 큰 구도를 먼저 잠근다.
Step 2.1 — Perspective Rig
카메라 위치·horizon line·vanishing point·support plane 수학적 고정. 이 단계 없이 배경은 공간적으로 붕괴된다.
Step 2.2~2.7 — Structural Preflight
오브젝트 인벤토리 → anatomy gate → object knowledge query → object research → 오브젝트 관계 검증 → 인체-오브젝트 관계 검증.
Step 2.8 — Blender 3D Blockout
장면 전체를 primitive 3D로 환원. clay / lineart / depth / normal / mask 패스 생성. ControlNet 가이드 소스.
Step 2.9 — Image Translation Lock
구조 / 접지 / 스케일 / 손-소품 관계를 non-negotiable lock으로 고정. 스타일은 그 이후.
Step 3~8 — Value / Face / Line / Color / Texture / Final
구조 위에 그림 요소를 쌓고 Step 8 Final Prompt Compiler에서 미학을 복원해 FINAL_IMAGE_PROMPT_COMPILED로 압축한다.
validate_illustrate_spec.py Gate
필드 누락·placeholder·theory proof 미생성·Blender 필드 누락 차단. 실패 시 해당 단계로 복귀.
run_illustrate_pipeline.py Gate
PIPELINE READY 최종 확인. 통과 시에만 FINAL_IMAGE_PROMPT_COMPILED 사용 가능.
Image Generation Handoff
3D 구조 증거(render passes)를 가이드로, 스타일 번역만 이미지 생성기에 위임.
